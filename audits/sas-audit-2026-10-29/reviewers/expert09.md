Add a small inventory verifier or invoke a real equivalent; run it both locally and in CI. Acceptance: an untouched candidate passes; changed hash, missing path and extra packaged path each fail with precise diagnostics; the documented command exists in the package. Do not simply remove the gate to obtain green CI.

**E09-F02 — P1, verified release inconsistency: inventory and version evidence describe different sources.** `README.md:1`, `tools/project_model.py:6` and `tests/browser/package.json:4` say 0.8.0; `plugin.json:4`, `capabilities.json:2`, `release/source-manifest.json:2` and `release/verification.json:2` say 0.7.1. Seventeen tracked additions are unlisted despite the manifest's “All packaged files” scope (`release/source-manifest.json:4`). This is stale release bookkeeping, not evidence of malicious modification. Choose one candidate identity and define whether the inventory represents the repository or an explicit distributable. Regenerate only after authorized implementation and verification. Acceptance: all declared current-version surfaces agree, every in-scope path hashes correctly, report records exact commit plus dirty overlay, and historical verification stays clearly historical. A consumer must be able to identify which source bytes a passing report tested.

**E09-F03 — P2, evidence-backed reproducibility risk: dependency capture is not the installed CI contract.** CI installs `requirements-validation.txt` (`ci.yml:26`), which pins three direct packages; the 19-package captured environment in `requirements-validation.lock:1-19` is unused and contains no distribution hashes. Pinning Playwright itself does not lock its resolved dependency graph, OS image or downloaded Chromium environment. This does not establish any present dependency exploit or install failure. Use a tested transitive Python lock with hashes, `--require-hashes`, and a committed Node lock with `npm ci`; record Python/Node/browser/OS versions in release evidence. Keep dependency refresh a deliberate reviewed operation. Acceptance: two clean builds from the same candidate resolve the same dependency versions and package inventory; changing a lock invalidates the relevant CI cache; unsupported Python/platform combinations are explicitly outside the tested matrix. README promises Python 3.10+ (`README.md:17`) while CI tests only 3.12; either cover the supported range or narrow the claim.

**E09-F04 — P2, verified observability defect: minimized receipts cannot distinguish a failed gate.** `tools/workflow_tools.py:96-101` defaults status to `completed`, records a fresh run ID and omits exit code, `ok`, `policy_ok` and failure counts. `architect_cli.py:75-77,99-102` writes that receipt before returning the gate's nonzero code; exceptions bypass receipt creation. Carry the operation's existing ID, input identity, terminal outcome, gate decision, exit code and status counts into the minimized record; distinguish execution completed from checks passed, including typed operation errors. Acceptance: passed, failed, blocked, timed-out, partial and input-error fixtures remain distinguishable without storing raw source, secrets or prompts; receipt and command output correlate exactly.

## What works and what remains bounded

`tools/safe_io.py:50-67,75-94,103-116` bounds regular-file reads/writes, refuses symlinks on supported POSIX paths, attempts fsync and serializes cooperating writers. `revision_store.py:50-76` validates recovery against authoritative project hashes; `artifact_compiler.py:122-174` separates committed generations from fallible legacy projections. These are useful local reliability mechanisms, not distributed transactions or certified power-loss durability. Preserve them and their candid limitations.

`validation_engine.py:203-237` provides killable process groups, output/CPU caps and optional memory caps; YAML receives 256 MiB. The OpenAPI worker call at `:319` does not supply a memory cap, and main-process parsing is not a universal resource sandbox. Strengthen measured process-wide bounds before serving untrusted multi-user workloads. There is no reason to add retries to local deterministic validation; retries for external execution must depend on idempotency and reconciliation, as the adapter already states.

A single local cold/warm scan read 47 eligible files and 324,683 bytes, visited 111 entries, extracted 206 declarations/203 edges and reported 39 omissions. Final probe timings were 0.166540 s cold and 0.011555 s warm, with 0/47 cache hits and identical source fingerprints. Both explicitly reported partial coverage. These are small-workload observations, not p95, throughput, semantic accuracy or capacity benchmarks. The cache still rereads/hashes all observed source bytes. A two-entry budget fixture stopped at two entries and correctly returned unknown unseen total plus partial coverage.

`tools/calculators.py:12-31` implements finite, unit-explicit scenario math, decimal-GB billing, optional assumed prices and omission disclosure. Preserve it. QPS/storage/network arithmetic does not determine required replicas, database indexes, queue saturation or sustainable throughput. Keep vendor prices unverified until sourced for an actual date/region/service; measure service demand and bottlenecks before recommending scale-out.

## Minimum operational contracts and milestones

**M09-A, release integrity, addresses F01–F03:** repair the inventory gate, reconcile candidate identity, lock actual CI inputs and capture current verification with commit/tool/environment identity. Retain the read-only CI permission and cancellation policy (`ci.yml:8-12`). Add finite job timeouts and artifact retention for browser traces/reports; current workflow provides no explicit job timeout or report upload. No publishing step is needed for this milestone. Its exit criterion is a reproducible candidate bundle with required failed/skipped checks visibly blocking the appropriate gate.

**M09-B, truthful operational evidence, addresses F04–F05:** implement shared typed terminal outcomes and descriptor diagnostics, then the small counterexamples above. Record duration, bytes, visited/read/extracted/omitted counts, cache hits, stop reasons and check-status counts locally. Remote analytics is unnecessary. Measure latency percentiles only over repeated fixed corpus runs with declared hardware, versions and warm/cold conditions.

**M09-C, optional operational handoff, addresses F06:** use existing NFR/task/evidence records plus one versioned operational extension. Required applicable fields: workload and concurrency; request success/latency SLI formula and measurement source; provisional SLO/window and owner; CPU/memory/disk/connection/queue limits; timeout/retry/idempotency/backpressure policy; dependencies; build command/toolchain/lock identity; deploy environment and immutable artifact identity; configuration/secret *references*; smoke/canary/abort predicates; migration compatibility and rollback/forward-fix decision; backup scope, retention, restore procedure, RPO/RTO and last drill receipt. Emit `operations.md` and machine-readable data, with explicit unknowns. Keep provider invocation in an authorized external runner under `docs/implementation-adapter.md:3-6`, not in the architecture compiler.

**M09-D, calibrated reliability exercises, depends on A–C:** propose a reference Linux 2-vCPU/4-GiB workload with 10,000 enumerated entries, at most 400 source reads/10 MB total and adversarial descriptors. Initial *targets to validate*, not achieved SLOs: terminal scan within configured deadline +1 s, validation within deadline +1 s, complete omission/status accounting and no surviving child process after timeout. Record peak memory and tighten ceilings after measuring; do not infer memory safety from file size alone. For local process-interruption recovery, propose zero loss of the last committed project and deterministic recovery within 60 s after the operator starts the documented procedure. Power loss, hostile writers and browser storage eviction remain separate unsupported failure models until drilled.

Failure injection should cover: interruption before/after project replacement and handoff-pointer publication; conflicting or corrupted journals; disk-full/permission denial; active versus stale lock ownership; absent validator; hung/noisy child process; malformed descriptors and cache reuse. Check original bytes remain recoverable, unowned edits survive, repeated recovery is idempotent, and no check becomes green through an omitted stage. The runbook starts by preserving canonical/journal/history/pointer bytes, identifying the authoritative commit point and writer, then running `recover` or `handoff-recover`; conflicts stop for reconciliation. Never automatically delete an unknown lock or prune history as “recovery.” Add cumulative history/generation disk accounting before retention automation.

For software the Studio helps design, choose availability, latency, cost and recovery targets from business criticality and measured workloads; no universal 99.9% or arbitrary database benchmark is justified here. A deployment receipt must separately establish built, tested, runtime-verified and deployed states, with environment identity, smoke evidence, rollback eligibility and remaining unknowns. No production-success claim is warranted from the inspected repository alone.
