## Upheld findings

**Receipt clobbering (E06-F01): uphold P1.** The explicit `--receipt` path supplies an output destination, but the interface does not communicate replacement of arbitrary existing content. `architect_cli.py:99` calls `record_run` after the primary operation; `workflow_tools.py:101` delegates to replace-capable `atomic_write` (`safe_io.py:75–94`). The recorded doctor reproduction therefore establishes ordinary accidental data loss, independent of an attacker. This is a more immediate integrity risk than hypothetical remote exploitation. A late receipt error can also conceal a successful primary commit, so preflight plus separate primary/auxiliary outcomes matter.

**Authentication drift (E06-F02): uphold P1 for review-ready handoff.** Truthy prose removes the authentication blocker at `artifact_compiler.py:19`, while the operation copy at `:81` contains no reconciliation of that prose. Retaining the string in `contracts.json` does not repair contradictory machine-consumable output. The report correctly avoids claiming a deployed unauthenticated endpoint. The minimum fix is typed intent and a conflict blocker, not guessing an OAuth implementation from words.

**Fitness false assurance and cache metadata loss (E04-F01/F02): uphold correctness findings.** `repository_evidence.py:188–189` uses matching observed bytes as sufficient clean-rule evidence; `:134–144` caches only declarations/edges. Unsupported language, failed extraction and quota omission cannot support absence claims. Critically, warm-cache promotion occurs without an adversary, whereas E06-F06's altered-cache scenario requires an opted-in editable cache. Fix ordinary semantic parity first, then define trust for imported caches.

**Change seeding and disappearing verifications (E04-F03/F08): uphold.** `graph_engine.py:58–61` seeds requirements only; `:36` projects reached nodes into core groups only. Existing diff/witness machinery can be extended locally. These are review-scope omissions, not proof that every reached artifact must change. The proposed typed seeds correctly preserve that distinction.

**Projection identity and schema/native mismatch (E06-F04/F05): uphold.** My independent export probe confirmed the former; the receipt schema's passed branch requires only property presence (`verification-receipt-v1.schema.json:139–143`), while runtime validation requires a non-null digest (`integration_contracts.py:100–102`). Equal representation hashes are legitimate; acceptance must compare each named hash to its actual representation, never demand inequality universally. Schema acceptance alone cannot authenticate a receipt.

## Revised interpretations and priorities

**E04 fitness exit zero is report behavior, not independently a broken CI exit gate.** `architect_cli.py:80` returns the report without a gate option. The falsely clean result remains a defect; explicit report/gate semantics are the remedy. Do not count every reported violation's exit zero as an additional false-success defect. P1 is justified before fitness is relied on for releases; it need not outrank direct data-loss repairs for casual inspection.

**Imported AGENTS instructions (E06-F03): uphold the dangerous transformation; condition the exploit claim.** Generation into an active host filename with reduced provenance is observed, but obedience, scope expansion and unauthorized effects were not tested. Preserve imported Accepted status. Default export to ordinary structured/quoted architecture data and reserve native instruction-file emission for an explicitly scoped operation. Keyword filtering and blanket reapproval are poor substitutes. Host permissions remain essential even with safer export.

**Cache poisoning, diagnostic disclosure, dependency drift and test-server exposure:** keep E06's conditional/local framing and P2. No remote exploit, actual dependency compromise or real credential disclosure was established. Validator raw errors genuinely can reproduce confidential synthetic values, but local diagnostics inherently share input confidentiality unless promised otherwise. Prefer safe shared defaults with explicit private debugging output. An all-interface repository-root server is a cheap test-harness repair; four passing Chromium cases do not prove loopback confinement or absence of sensitive file serving.

**Coverage expansion:** E04's parser/declaration findings justify precise adapters and status fixes. They do not justify a universal semantic graph, whole-language handwritten parser or hosted security platform. The 0.253-second cooperative deadline overrun demonstrates enforcement limits, not an unbounded denial-of-service exploit. Measure worker overhead before isolating every tiny parser.

## Missing controls in the proposed engineering contracts

The seven specs substantially address identity, format parity, scope semantics, render outputs, state envelopes and source-bound receipts. Add these acceptance-level obligations before implementation handoff:

1. **SPEC-04/06 auxiliary ownership:** receipts/caches/diagnostics cannot overwrite canonical, source, unrelated or reserved control files. Preflight collisions before primary mutation; preserve committed primary state if auxiliary publication later fails. Test fresh, existing, symlink and hardlink-alias destinations. Atomic replacement of a hardlink path does not necessarily mutate the other link; assert preservation precisely rather than inventing a hardlink exploit.
2. **SPEC-01/02 authentication fidelity:** typed unspecified/public/required intent, explicit schemes/scopes, root inheritance and operation override rules; prose-only or conflicting protection blocks review-ready correspondence. Publish resolved policy in security documentation.
3. **SPEC-01/06 authority provenance:** ordinary handoff must not activate imported prose as host instructions. Preserve record IDs/origins; actual host authorization covers reads, process effects, network/secret access and writes, not only deployment. Test evidence-status manipulation as well as scope expansion.
4. **SPEC-05 evidence trust and relation types:** cold/warm semantic parity is necessary but insufficient for untrusted caches. Release/security gates re-extract or require host-established cache provenance. `forbid_import` must examine supported import relations, not arbitrary `package-depends-on`/jobs `depends-on` edges; current fitness filters no edge kind (`repository_evidence.py:187`). This is a source-backed additional risk, not a newly executed reproduction.
5. **SPEC-02 status migration/privacy:** retain or explicitly map current `tool_error` and `not_run_due_to_budget`; neither disappears into pass. No rule-coverage record means incomplete, not inapplicable. Default shared diagnostics contain bounded codes/pointers and identities; raw exception/stdout values require an explicit private artifact.
6. **SPEC-07 test boundaries:** loopback-only fixture-root HTTP server; locked resolved dependencies and exact browser/tool identities; required browser checks declared separately from DOM-model tests. Never infer broad accessibility or security assurance from four passing cases.

Minimum acceptance is the existing failing suite repaired without weakening invariants, regression fixtures for these boundaries, source/format/cache equivalence matrices, schema/native receipt parity, and independently checked actual artifact identities. Residual uncertainties remain host obedience, real renderer behavior, non-POSIX races, hostile concurrent writers, dependency vulnerability freshness and representative model quality. Keep them explicit rather than converting a comprehensive test plan into completed evidence.
